# 产品定义

## 产品描述

52Hz 是一种以拼音为基础、由大语言模型驱动的智能输入系统。用户连续输入整段话，在光标处看到系统猜出的表达，按一次空格即可结束输入。目标是 99% 的日常输入都能这样一次完成，不需要看候选框，也不需要事后改字。

## 目标用户体验

用户不需要先思考“应该怎样按照输入法规则输入”，而是可以直接输入接近自己想法的内容。

例如，用户可能输入一段连续的、带有错误的拼音：

```text
nihaocodex,woxisngshixiamyigeshufaru
```

这段输入可能同时包含：

- `a -> s`、`n -> m` 等相邻键误触
- 拼音边界缺失
- 音节块顺序变化
- 英文名称和中文拼音混排
- 标点直接出现在输入流中

系统应该结合整句、设备错误模型和上下文，恢复用户意图，而不是要求用户逐个候选词确认。

## 交互策略

### 输入、结束和主动修改

| 用户动作 | 输入法行为 |
| --- | --- |
| 连续输入 | 在组合态内预览整段首选，保留原始按键供继续输入、退格和重新判断。默认不弹候选框；预测再有把握，也不因停顿而提前上屏。 |
| 按空格结束 | 空格表示“这段打完了”，不是选择第一个候选。结合整句、当前上下文和可用的个人记忆，若意图已明确，直接提交；若仍有实质歧义，只展示一处的选项。没有组合文本时，空格仍是普通空格。 |
| 主动按 `More` | 即使首选很明确，用户也能查看并替换光标所在片段。选完重新评估整句，回到编辑，不自动提交。`More` 是操作名，具体键位未定。 |

有第二种拼写或解释，本身不是弹框的理由。只有用户主动要改，或结束输入时结合现有信息仍分不清几种合理含义，才展示候选。如果没有可信结果，也不应为了上屏而编造选项；保留原始输入供继续编辑。已提交的结果仍可撤销或修改。

### 多处歧义：每选一处，重新判断整句

一次只展示一个片段的选项，优先询问最有助于判断其余部分的一处。用户的选择是本次输入的约束：除非用户主动改动，重新推断不能推翻它。不要预先排好一串问题让用户逐一回答。

例如输入 `mingtianzhaolixinkaihu` 后按空格。假设个人记忆里有同事“李欣”和银行客户经理“李鑫”，整句仍不足以判定人名和动词：先只问“李欣 / 李鑫”。选了“李鑫”后，如果上下文已经足以判定“明天找李鑫开户”，就直接提交，不再问“开会 / 开户”，也不需要再按空格。如果动词仍判不准，才展示第二处选项。

### 验收：同一串按键，不同意图

以 `mingtiankaihu` 为例：`kaihu` 既可以是“开户”的完整拼音，也可以是“开会”漏了末尾的 `i`。两种解释都必须保留到整句判断，不能因为拼音恰好合法就直接锁定“开户”。

| 输入时已知的信息 | 预期行为 |
| --- | --- |
| 正在讨论如何对齐项目进度 | 光标处直接预览“明天开会”，不等用户补 `i`。此时按空格即提交；若用户先补 `i`，预览仍是“明天开会”。 |
| 正在讨论办理银行卡 | 同样的按键预览“明天开户”，空格提交，不弹框。若用户主动按 `More` 改选“开会”，保留其选择并返回编辑。 |
| 两件事都在讨论，个人记忆也不能区分 | 按空格后只问“开会 / 开户”。选好即提交整句，不要求重打。 |

**整段一次成功率（目标 99%，不是已测结果）**：在代表日常输入、标有预期整段文本的评测集中，以全部输入段为分母；只有按一次空格后首选全文正确、未展示候选且不需要修正的段才计入分子。正确地询问歧义是合理行为，但不计为一次成功；静默上屏却猜错同样不计。另行记录误提交和主动询问，不能用“不弹框率”或模型给出的置信分数代替这个指标。

## 核心能力

1. 连续拼音和长句理解。
2. 中文、英文、数字和符号混输。
3. 基于设备的相邻键误触建模。
4. 漏按、多按、替换和局部转置的容忍。
5. 结合上下文恢复完整表达。
6. 用户自定义词汇和个人错误模式学习。
7. 本地模型、远程模型和规则模型的统一接入。
8. 自动提交的撤销和低置信度降级。

## 不同于传统输入法的地方

传统输入法通常是：

```text
标准拼音 -> 词典候选 -> 用户选词 -> 提交
```

52Hz 的目标是：

```text
带噪声输入 + 设备 + 上下文 -> 意图解码 -> 直接表达
```

候选词不再是主要产品体验，语言模型和设备感知的噪声解码才是核心。
